  `app.ingestion.seed`. Flags: `--only <substr>` filters the SEED_URLS

  calls), `--force` re-ingests duplicates, `--yes` skips the
  interactive confirm. Before each ingest it queries
  `documents.source_url` and skips the URL if already present, so a
  partial run can be Ctrl-C'd and re-run safely.

**Phase 2 — answer quality (S10 groundedness + S8 safety):**

- **Real bug found while reading.** In `orchestrator.py` the
  `legal_qa` path calls `Retriever(self.db).search(user_message)`,
  formats the result into a `context` string, then **never passes it
  to `LawyerAgent`**. The agent then has to re-discover the chunks via
  its `legal_search` tool inside the ReAct loop. Two costs: a wasted
  embed call on every `legal_qa`, and zero guarantee of grounding if
  the model decides the tool isn't needed. This is exactly the kind of
  thing the rubric scores as a "groundedness" failure. Fix: added
  `context: str | None = None` to `LawyerAgent.__init__`, the agent's
  initial messages now include
  `CITATION_GROUNDING_INSTRUCTION.format(context=context)` between
  `LAWYER_SYSTEM_PROMPT` and the ReAct instructions. `legal_search`
  stays available for follow-up refinement.
- **Deterministic empty-context refusal.** Added
  `NO_CONTEXT_REFUSAL_UZ` and `NO_CONTEXT_REFUSAL_RU` constants in
  `prompts.py`. `LAWYER_SYSTEM_PROMPT` rule 2 now requires those exact
  strings when context is insufficient (belt-and-braces). The
  orchestrator short-circuits to the language-appropriate phrase
  before any LLM call when `Retriever.search()` returns `[]`. Sets
  `refused=True` on the result; `chat.py` refunds the free-plan query
  slot when `refused` so legitimate refusals don't burn a user's
  monthly quota. Mirrored the same short-circuit in
  `app/rag/pipeline.py` for non-orchestrator callers, with a Cyrillic-
  character heuristic for language detection.
- **14 more tests** (7 for Phase 1 tools, 7 for Phase 2 grounding +
  refusal). All 26 pass at the end of the day.

## Problems encountered

1. **CI hadn't actually run on `master` since 2026-05-13.** The
   workflow's trigger is `on: push: branches: [main, develop]`, and the
   actual branch name is `master`. So every commit since then bypassed
   CI. Opening PR #1 was the first time the lint + tests ran on the
   accumulated work — and surfaced **20 ruff errors** in total. 9 were
   mine (my Phase 0 sentinel constant landed between import groups,
   triggering 9 × `E402`). 11 were pre-existing: 3 `E402` in
   `app/api/multimodal.py` (a `_DOCX_MIME = ...` line between imports,
   from commit `3708de8`), 4 `F401` unused imports across
   `telegram.py` / `payme.py` / `storage.py`, and 4 `F821` in
   `app/models/*.py` from SQLAlchemy 2.0 `Mapped["X"]` string forward
   refs that ruff misreads as undefined names.
2. **Frontend `next lint` hung the CI runner.** The frontend has no
   `.eslintrc.json`, so `next lint` dropped into its interactive
   setup wizard ("How would you like to configure ESLint? > Strict /
   Base / Cancel") and waited for stdin. CI eventually killed it. Also
   pre-existing — exists on `master`, just never ran there.
3. **Pre-existing test bug: regex didn't match its own test case.**
   `tests/test_guardrails.py` asserts the injection regex catches
   `"Disregard the prior rules."`. The regex was
   `disregard .* (instructions|system prompt)` — `"rules"` not in the
   alternation. Same author wrote the test and the regex; never
   re-ran on master to notice.

## Solutions

1. **Mine:** moved the sentinel below all imports in `auth.py`.
   **Pre-existing E402s:** moved `_DOCX_MIME` below imports in
   `multimodal.py`. **F401s:** deleted the unused imports.
   **F821s:** added a 4-line `backend/ruff.toml` with
   `[lint.per-file-ignores] "app/models/*.py" = ["F821"]` — string-
   typed `Mapped["Document"]` is intentional in SQLAlchemy 2.0, not a
   bug. Ruff went from 20 errors to 0.
2. Added `frontend/.eslintrc.json` with
   `{ "extends": "next/core-web-vitals" }` — same content the
   "Strict (recommended)" prompt would have created. `next lint`
   stops asking and runs.
3. Added `rules` to the alternation in `app/security/guardrails.py`.
   One-word fix, all 28 backend tests green.

After 3 push cycles, both `backend` and `frontend` checks are green,
