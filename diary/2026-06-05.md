# 2026-06-05 — Week 4: a real prod bug (Neon idle-in-transaction), corpus expansion, the free-tier quota wall

## What was done

Shipped the app to prod yesterday; today was about feeding it a real legal
corpus — and that immediately surfaced a genuine production bug I had to hunt
down and fix before anything would seed.

Applied from the mentor sessions: **S9 (data engineering)** — ingestion
pipelines must be idempotent, re-runnable, and resilient, and embedding is an
I/O-heavy step that must *not* be done while holding a database transaction
open. That last point is exactly what bit me.

- **The bug.** `ingest_document` created the `Document`, `flush()`ed it (opening
  a transaction), then embedded *all* of the document's chunks — hundreds of
  rate-limited Gemini calls, ~9 minutes for a big code — and only committed at
  the end. On Neon that's fatal: the connection sits **idle inside an open
  transaction** for those 9 minutes, Neon's `idle_in_transaction_session_timeout`
  fires and terminates it, the final `UPDATE … status='embedded'` blows up, and
  the now-rolled-back session **poisons the next URL's dedup query** (a
  `PendingRollbackError` cascade). The 1,125-chunk Civil Code never landed.
- **The fix.** Reorder so embedding happens *before* the write transaction:
  roll back any open read transaction, embed with the connection idle-clean,
  then write the document + all chunks in **one short transaction**. A failed
  embed now raises before any row is written (no orphan `pending` doc). I also
  made the seeder `rollback()` after a failed URL so one failure can't poison
  the rest of the run.
- **Corpus expansion.** Ran a research-and-verify pass over ~16 more Uzbek
  codes/laws: for each, search for the lex.uz document id, then **verify it by
  actually running the project's scraper** (confirm the real title + that the
  body is a substantial legal document). 14 passed — Housing, Budget,
  Town-Planning and Economic-Procedure codes, plus the Consumer-Rights, LLC,
  Joint-Stock, Notary, Employment, Personal-Data, Mortgage, Appeals, Bankruptcy
  and Entrepreneurship laws. Customs and Air codes were **rejected** (their
  candidate URLs 404). No hand-guessed ids reached the corpus — a deliberate
  guard, because a wrong id silently seeds the wrong document.
- **Result.** Re-ran the seed against prod with the fix: the Civil Code Part 1
  committed cleanly (fix validated against the exact doc that failed before).
  `/health` `chunks_count` went **795 → 1,920**.

## Problems encountered

1. The idle-in-transaction crash above (twice, before I understood it).
2. **Gemini free daily quota.** Civil Code Part 1 alone (~113 embed batches)
   drained the daily embedding quota across all 4 of my keys; every document
   after it failed with "All 4 Gemini API keys hit quota." The remaining ~30
   docs (Civil Pt 2, Labor, Criminal, Tax, Admin, both procedure codes, Family,
   Land + the 14 new ones) are blocked until the quota resets.
3. A transient DNS failure resolving the Neon host crashed the tail of the run
   — a network blip, not a code problem.

## Solutions

1. Embed-before-transaction reorder — validated on real Neon (Civil Pt 1 now
   commits). Tests updated, ruff clean, merged.
2. No code fix possible for the quota — it's the free-tier ceiling. The levers
   are: wait for the daily reset and re-run (the seed is idempotent, so it
   skips what's already in and adds more each cycle), or add more
   comma-separated Gemini keys for more quota per run. Documented both.
3. The per-URL `rollback()` means the quota failures no longer cascade — the
   run now walks the whole list gracefully instead of dying on the first
   failure. The DNS blip is transient; re-running resumes cleanly.
