# 2026-06-13 — Brain transplant (Gemini → Claude) and the four prod fires it lit

Switched the chat LLM from Gemini to **Claude via the AssemblyAI LLM Gateway**
(OpenAI-compatible). The migration itself was one line of config; what followed
was a cascade of production failures, each one masking the next.

## What I did

- **Provider migration.** Wired the Render blueprint for the gateway:
  `LLM_PROVIDER=openai`, `OPENAI_BASE_URL=…assemblyai…/v1`,
  `LLM_MODEL=claude-sonnet-4-6`; the only secret is the gateway key. Embeddings +
  OCR/voice stay on Gemini (the gateway is text-only).
- **Config self-heal guard.** If `LLM_PROVIDER=gemini` but `LLM_MODEL` is a
  non-Gemini name (e.g. a Claude model pasted in by mistake), it now falls back
  to `gemini-2.5-flash` instead of 404-ing every chat against Google's API.
- **Decoupled multimodal from the chat model.** Image/voice code was calling
  Gemini's SDK with `settings.LLM_MODEL` — now a Claude name — so uploads 404'd.
  Added a dedicated `GEMINI_MULTIMODAL_MODEL` so vision/OCR/voice always use a
  valid Gemini model regardless of what the chat model is.
- **Fixed empty answers.** The `LawyerAgent`/`AnalyzerAgent` ran a JSON ReAct
  tool-loop tuned for Gemini. Claude emits several `legal_search` calls at once
  and never a clean `final`, so it spent all 5 steps and returned its give-up
  message. Since the orchestrator already retrieves the context, both agents now
  answer **directly** with one grounded synthesis when context is present (ReAct
  stays only as the no-context fallback).
- **Fixed the empty SSE stream.** `/chat/stream` returned a 200 with **zero
  frames** in prod — the streaming generator runs after the request's
  `Depends(get_db)` session is closed, so the first query failed before any
  token. Gave the generator its own `SessionLocal()`; the client also falls back
  to the blocking `/chat` if a stream yields no tokens.
- **`/health` diagnostics** (provider, model, base URL, which keys are
  configured) so the deployed config is visible without the dashboard.
- **Corpus + payments.** Seeded the Consumer Rights Law + Land/Housing/Budget
  codes; turned the Click checkout into a QR modal (scan to pay) with a web
  fallback; hid Payme for now.

## Problems encountered

- A four-stage failure chain where fixing one bug only revealed the next: model
  name → 404 on chat → 404 on image upload → empty "step budget" answers → empty
  SSE stream. The blocking `/chat` worked the whole time, which masked the
  streaming bug.
- The **free-tier Gemini embedding quota** caps how much corpus I can seed per
  day — the major codes (Labor/Criminal/Tax/Family) are still pending.

## Solutions

- Reproduced each failure locally against the real gateway key before pushing,
  rather than debugging blind on prod. Verified end-to-end on prod afterwards:
  `/chat/stream` now emits `meta` + 51 token frames + `done`, with citations
  (Fuqarolik kodeksi Art. 337).
- Made the seeder resumable (skips already-embedded docs) so it converges over
  multiple runs once quota frees up.
