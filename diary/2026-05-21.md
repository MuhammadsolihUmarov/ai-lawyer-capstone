# 2026-05-21 — S5 (Agents): multi-agent layout + memory + streaming

## What I did

Refactored AI Lawyer from a single LLM-call-per-question pipeline into a proper **multi-agent architecture** with shared memory and intent routing. This is the equivalent of Ilm AI's "learning plan agent + gap detection" — same shape, different domain.

- **Router agent.** Classifies every incoming message into one of `{legal_qa, doc_draft, doc_analysis, chitchat, out_of_scope}` and emits a language tag (`uz` / `ru` / `en`). Implemented as a JSON-mode Gemini call with `temperature=0`. Out-of-scope messages get a canned refusal in the detected language — no retrieval, no LLM cost.
- **LawyerAgent.** Handles the `legal_qa` branch. Calls the hybrid retriever, then synthesizes an answer with citation-strict prompt (`LAWYER_SYSTEM_PROMPT` in `app/llm/prompts.py`). The prompt enforces: cite real articles only, never invent article numbers, distinguish text vs interpretation vs guidance, append a one-line disclaimer.
- **AnalyzerAgent.** Handles `doc_analysis`. Loads chunks by `document_id` (the previous orchestrator was incorrectly loading by `conversation_id` — that was a real bug, fixed today). Returns structured extraction with grounding back to the uploaded doc's chunks.
- **DrafterAgent.** Handles `doc_draft`. Picks a template from the 5 (contract / claim / complaint / statement / power of attorney), fills it, attaches a citations footer verified against the corpus.
- **ResearchAgent.** Sub-agent the LawyerAgent can call via a tool when the question requires multi-step retrieval (e.g., "compare the labor and civil treatments of compensation"). Returns a digest of relevant articles, doesn't write the final answer.
- **`UserMemory`.** Cross-conversation key-value store on the user. Each agent can read / write summaries like *"user is an HR officer", "asked about Art. 134 last week"*. This is the AI Lawyer equivalent of Ilm AI's gap-detection — it gives the model a stable persona for the user across sessions, so answers can be tailored without re-asking.
- **SSE streaming endpoint `/chat/stream`.** Token-by-token streaming so the UI doesn't block on slow LLM responses. The existing `/chat` endpoint stays for clients that prefer the simple JSON response.
- **Per-token quota.** Migration `0003` added `subscriptions.monthly_tokens_left` (default 200,000). Both `/chat` and `/chat/stream` debit tokens after each call. This sits alongside the existing `monthly_queries_left` check.

## Problems

1. **Docker Desktop crashed mid-migration.** Background command died with exit code 1; on retry, `docker info` reported "Docker Desktop is unable to start." This was during the `alembic upgrade head` run inside the backend container, so the migration was half-applied (0001 done, 0002 partial).
2. **The rate-limit middleware uses `request.client.host`** as the bucket key. Behind Render's proxy, that resolves to the **shared proxy IP**, not the real user IP. So 30 calls per 60 seconds is a **global** limit across all users — not per-user. Discovered this when probing the deployed `/chat` and getting `429` after a single call (the bucket was full of other traffic).
3. **JWT auto-expires after 60 minutes.** A long eval run that starts with a 38-min-old token will hit `401` mid-stream. Hard to debug because the failure mode is silent — answers just go to N/A in the eval report.
4. **Doc-analysis bug, pre-existing.** The old code loaded `chunks` by `conversation_id` for the analyze flow, which meant uploading a contract returned chunks from unrelated past conversations. Found it when writing the AnalyzerAgent.

## Solutions

1. Forced Docker Desktop to restart by killing the desktop process tree and re-launching from `Program Files`. Docker recovered after ~30s. Then re-ran `alembic upgrade head` against the local Neon shadow — migrations are idempotent so the partially-applied state finished cleanly.
2. **Hot-fix:** raised the per-bucket cap to keep the live bot usable (`LIMITS = [("/chat", 60, 600), ...]`). **Real fix (next):** key the bucket by JWT subject (the user's email) instead of `request.client.host`. Until that lands, the 600/60s ceiling is a temporary widening; committed as a TEMP commit so it's obvious in `git log`.
3. The eval runner needs an auto-refresh of the JWT mid-run. For today I just regenerated the token before kicking off, but the proper fix is a `refresh_token_if_expired()` wrapper around `call_chat`.
4. Fix was three lines in the orchestrator: pass `document_id` through `ChatIn`, route doc-analysis to a `chunks WHERE document_id = ...` query, and write the `AnalyzerAgent` that consumes those.
