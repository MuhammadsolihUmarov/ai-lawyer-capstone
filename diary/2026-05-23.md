# 2026-05-23 — S6 (Orchestration): chat UX overhaul + eval harness + production push

## What I did

Polish day. Frontend got a proper layout, the prompt got brevity rules, and the evaluation infrastructure now exists end-to-end. Also did the deferred secret-removal that's been sitting in the rubric's "no hardcoded secrets" deduction column.

- **Frontend "Justice & Order" redesign.** Parchment background + navy primary + brass accent. Custom Tailwind theme tokens (`bg-parchment-100`, `text-ink`, `border-rule`, `text-brass-500`, etc.). The chat page got a Claude/ChatGPT-style left sidebar: `+ New chat` button at the top, conversation history scrollable in the middle (loaded from `GET /chat/conversations`, clicking a row loads `GET /chat/conversations/:id`), language switch + logout in the footer. Collapses below `md:` breakpoint into an inline header with `New` and `Logout` buttons.
- **Brevity prompt.** Old `LAWYER_SYSTEM_PROMPT` produced 6–8-sentence answers with `(a) text (b) interpretation (c) guidance` structure on every reply, including for one-line factual questions. Rewrote with explicit rules: default to 2–4 sentences + citation, drop the three-part structure unless the user explicitly asks for detail (`"in detail" / "tushuntiring" / "подробнее"`), skip the disclaimer on chitchat and one-line answers.
- **`app.title` shortened.** Removed the `— O'zbekiston` / `— Узбекистан` suffix from the chat header. The product name is "AI Yurist" (uz) / "AI Юрист" (ru), the country qualifier was crowding the mobile header.
- **Telegram token removed from code.** `TELEGRAM_BOT_TOKEN` is now `""` by default — must be supplied via Render env var. Order of operations matters: set the env var on Render FIRST, only then push the code change. Otherwise the bot dies on the next auto-deploy. Pushed as `4fe1fea`.
- **Eval harness.** Golden set expanded from 22 → **50 questions** across 9 areas of Uzbek law (Labor +5, Civil +5, Criminal +5, Tax +4, Family +4, Administrative +2, Land +2, Housing +1, Constitution +1). Roughly 56% uz / 44% ru. Written `backend/eval/run.py` — POSTs each question to `/chat`, captures the answer + citations, then calls Gemini-as-judge with a strict rubric prompt for 4-axis scoring: **accuracy / groundedness / helpfulness / tone**, each 0–5. Writes a Markdown report to `docs/eval_report.md` with aggregates, per-language recall@5, score distribution, and failure analysis. CLI flags `--max`, `--sleep`, `--out`. Resilient to `/chat` 5xx and judge JSON-parse failures.
- **Payment proof template.** `docs/payment_proof.md` — end-to-end Click + Payme sandbox walkthrough using the real handler signatures (`click_payment.handle_callback`, `payme.handle_rpc`, `payme.authorize`). Includes verification SQL against the actual `subscription.py` columns (`monthly_queries_left`, `monthly_tokens_left`, `external_id`, `paid_at`) and the Payme JSON-RPC error codes (`-31050`, `-31051`, `-32601`) that the handler actually raises.

## Problems

1. **Eval JWT expired mid-run.** First eval attempt got `401` on questions 14+ because the token issued ~38 minutes before the run hit its 60-minute TTL during execution.
2. **`/chat` rate-limit blocked the eval.** The middleware buckets are keyed by proxy IP (a known issue from the 21st), so the eval runner — coming from a single IP — got `429` after one or two calls. Five rapid retries on the same IP didn't help; the bucket needed ~60s to drain.
3. **Eval runner ran for 25 minutes and finished with `0/51` recall**, because the combination of (rate-limited start) + (JWT expiry during the long 429-retries) wiped the run. The Markdown report wrote fine but every row was N/A.
4. **Rubric interpretation confusion.** Spent time reading the program README and worrying that AI Lawyer would lose 20+ points for not having quiz mode / learning plan / gap detection — features specific to Ilm AI (the program's default capstone). The brief seemed to imply those features were required.

## Solutions

1. Added retry-on-429 with exponential backoff to `call_chat` in `backend/eval/run.py` (8s → 12s → 18s → 27s → 40s, capped at 45s, max 6 attempts). The next eval also gets a fresh token immediately before the run starts — JWT lifetime resets to a full 60 minutes.
2. **Temporary widening:** raised `LIMITS = [("/chat", 60, 600), ...]` in `app/security/rate_limit.py` so the live app stays usable while I'm hitting it from a test rig. Committed with a `TEMP:` prefix so it's obvious in `git log` and easy to revert. **Permanent fix (deferred to next week):** key the bucket by JWT subject so per-user limits work behind the proxy.
3. Re-running tonight with a fresh token, the new retry logic, and the higher rate limit. Will paste actual numbers into `docs/eval_report.md` once it completes.
4. Found the program statement that clarifies this: *"Your product may not have a 'quiz mode' or a 'Telegram bot', but it should hit the equivalent stage at each milestone."* So AI Lawyer's `LawyerAgent / AnalyzerAgent / DrafterAgent` + `UserMemory` are scored as the equivalents of Ilm AI's `learning_plan_agent + gap_detection`. Re-grading the project: previous estimate 80/100, revised to ~85/100, with a path to ~92/100 once the eval numbers are filled and a Click sandbox payment is captured.
