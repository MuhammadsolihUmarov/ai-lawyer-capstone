# 2026-05-19 — Week 2 kickoff: hybrid retrieval + drafting + multimodal analyze

## What I did

Today was the start of **Wave 1** — the feature push that gets AI Lawyer from "passable RAG demo" to "real product with three workflows" (chat, analyze, draft).

Scoped four parallel tracks and assigned each to its own implementation pass:

- **Track A — Drafting.** Five Jinja2 templates (uz + ru) for contracts, claims, complaints, statements, and powers of attorney. DOCX export via `python-docx`. New `/draft` FastAPI router and a `/draft` wizard page on the frontend. Citation verification at template-render time so the generated document footer references real, retrieved articles — not hallucinated ones.
- **Track B — Hybrid retrieval + reranker.** Migration `0002_chunks_fts` adds a `tsvector` column to `chunks`, a GIN index, and a `BEFORE INSERT OR UPDATE` trigger that recomputes `tsv` from `text` on every write. `Retriever.search_hybrid` runs vector (pgvector cosine) and lexical (Postgres FTS) in parallel, fuses with **Reciprocal Rank Fusion at k=60** (the value from Cormack et al. 2009 — it damps low-ranked items so the top of one ranker can't be drowned by the bottom of the other). Then `Reranker` (LLM cross-encoder, prompt in `app/rag/reranker.py`) re-scores the top 20 down to the final top 6.
- **Track C — Multimodal analyze.** New `/multimodal/extract` endpoint that takes a PDF / DOCX / image, runs Gemini vision with a JSON-schema prompt, and returns structured `{parties, dates, claims, obligations, recommended_actions}`. New `/analyze` page on the frontend with a chat-prefill handoff so a user can extract a contract and then ask follow-up questions about it.
- **Track D — Chat core hardening.** Migration `0003_token_quota` adds `subscriptions.monthly_tokens_left` (default 200000) so I can quota by tokens, not just by query count. New SSE streaming endpoint `/chat/stream`. Cross-conversation `UserMemory` shared by `LawyerAgent` and `AnalyzerAgent` so the model remembers context from earlier sessions.

Wave 1 ships as a single squash commit (`b612f14` on master).

## Problems

1. **The four tracks didn't compose cleanly.** Track B and Track D both touched `Retriever` and the chat orchestrator. The agents produced overlapping diffs that didn't merge — one rewrote the retriever module, the other added a new code path that imported from the old structure.
2. **`STORAGE_BACKEND` env var parsed wrongly inside Docker.** The line `STORAGE_BACKEND=local       # local | s3` in `.env` was being read by `docker run --env-file` with the inline comment as part of the value, then pydantic-settings rejected it as not matching `Literal["local", "s3"]`. Tests failed during the build.
3. **One sub-agent wrote `test_retriever_modes.py` that initialized `GeminiEmbedder` eagerly in the fixture**, so the test couldn't even be collected without a valid `GEMINI_API_KEY`. CI broke.
4. **Hardcoded Telegram bot token in `config.py`** was flagged by a security audit pass — the kind of thing the rubric calls out under "Code Quality / no hardcoded secrets."

## Solutions

1. Ran an integration audit pass after each agent finished, then a final cross-cutting audit that produced a single coherent diff. The audit was its own sub-task with a narrow brief ("reconcile these two diffs"). It saved me from a multi-hour manual merge.
2. The fix is to strip the inline comment from `.env`, but for the test run I added `-e STORAGE_BACKEND=local` as an explicit override on the `docker run` invocation. The underlying bug is python-dotenv strips inline comments, Docker's `--env-file` doesn't.
3. Extended the test's `skipif` guard to also check `EMBEDDING_PROVIDER=local` OR `GEMINI_API_KEY` set, so the test self-skips cleanly when run without an embedder configured.
4. Decided to defer the token rotation to a later commit — the rule I now follow strictly: **set the deploy env var FIRST, only then remove the hardcoded credential**. Today the token stays in code; tomorrow I'll set `TELEGRAM_BOT_TOKEN` in Render env and remove the default.
